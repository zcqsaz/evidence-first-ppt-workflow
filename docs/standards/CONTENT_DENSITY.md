# Content, language, and density standard

## 1. 信息密度的定义

信息密度不是字数多，也不是把字号缩小。合格页面应在可读范围内形成一个完整论证单元：

```text
明确结论
+ 至少4条实质知识点/证据
+ 必要图、公式或表格
+ 适用条件或误差边界
+ 页内来源
```

除封面、目录和真正的过渡页外，正文有效区不足约60%，且仍有明显可补内容时，判为低密度。

## 2. 页面类型

### 2.1 图文页

必须有：

- 一句中心结论；
- 一幅完整、可读、直接相关的图；
- 中文图题；
- 3—4条观察或解释；
- 一条适用边界；
- 页脚来源。

### 2.2 公式页

必须有：

- 公式解决的问题；
- 正确渲染公式；
- 参数/符号解释；
- 适用条件；
- 参数敏感性或误差来源；
- 方法文献。

### 2.3 文字页

推荐两组互补内容：

- 定义、原理与实现：约4条；
- 参数、适用条件与误差：约4条。

不得使用八条空泛短语充数。

### 2.4 表格页

适合真正的比较关系。至少需要清晰表头、3—4行内容和页底结论。列表不应强制改成表格。

### 2.5 技术路线页

不能只有一张流程图。至少解释输入、关键处理、输出、质量控制、验证和失败风险。

## 3. 课程语言

课程PPT使用知识讲授语言，不使用项目申请书式语言。

禁止写入页面：

- 阅读要点；
- 课堂解读；
- 课堂观察；
- 理解要点；
- 案例定位；
- 课程示意；
- 图示所支持；
- 核心内容；
- 制作说明；
- 仅供AI/仅供制作助手；
- 模块一/模块几。

允许的学术层级标题：

- 定义与原理；
- 参数与边界；
- 方法比较；
- 误差来源；
- 适用条件；
- 质量控制；
- 验证与不确定性。

## 4. 项目汇报语言

项目汇报可以使用“研究内容、技术路线、关键技术、创新点、年度计划”等结构，但必须避免：

- 只重复申请书长句；
- 只有任务名称没有技术内容；
- 把预期目标写成已完成成果；
- 创新点缺少与现状对比；
- 技术路线只放流程图不解释关键决策。

## 5. 内容压缩顺序

空间不足时依次删除：

1. 重复修饰语；
2. 同义解释；
3. 可进入讲稿的背景；
4. 次要案例。

不得优先删除：

- 变量定义；
- 适用条件；
- 质量控制；
- 不确定性；
- 尺度限制；
- 来源。

## 6. 低密度修复顺序

```text
补充直接相关的真实证据
→ 补充公式或参数解释
→ 使用原生学术表格
→ 增加实质课程文字
```

禁止用装饰框、无关图标、放大标题或重复图片填空。

## 7. 同质化检查

同一模板内使用2—3种版式构图。相邻两页至少改变以下一项：

- 主视觉位置；
- 阅读方向；
- 证据类型；
- 图文比例；
- 信息层级。

只替换文字和图片、其他位置完全不变，判为机械重复。
