# Governance, privacy, and release policy

## 1. 规则级别

工作流规则分为：

- `MUST`：交付门禁；
- `SHOULD`：推荐默认值，可记录理由后偏离；
- `MAY`：可选实践；
- `EXPERIMENTAL`：尚未形成稳定接口，不应作为强制依赖。

任何新增 `MUST` 规则必须同时提供检查方式、失败示例和返工入口。

## 2. 版本管理

采用语义化版本：

- MAJOR：目录、Schema或验收语义不兼容；
- MINOR：新增兼容规则、模板或检查器；
- PATCH：修正错误、表述或实现缺陷。

项目应在交付报告中记录所用工作流版本。

## 3. 隐私和保密

默认不公开：

- 原始PPT、Word、PDF和数据；
- 未发表论文、项目申请书和内部报告；
- 姓名、邮箱、位置、账号和访问令牌；
- 含个人信息的照片或截图；
- 机构内部模板和未公开成果。

公开示例必须为合成内容、公共领域内容或明确允许再分发的内容。

## 4. 版权和商标

元数据、引用和URL不代表取得图片再分发权。公开仓库可仅发布：

- 文件名和元数据；
- 原始来源链接；
- 获取脚本；
- 不包含受限二进制文件的使用说明。

机构名称、徽标和模板仍受相应权利人约束。

## 5. 决策记录

以下决策需要写入项目变更记录：

- 改变主叙事；
- 增删章节；
- 更换模板或字体；
- 引入无法公开的素材；
- 批准重复使用同一科研图；
- 允许带裁剪的非科研实景照片；
- 接受未通过自动检查的例外。

## 6. 发布清单

公开发布前确认：

- [ ] LICENSE、NOTICE、CONTRIBUTING存在；
- [ ] 无真实项目输入和交付文件；
- [ ] 无本机绝对路径；
- [ ] 无密钥、账号和内部链接；
- [ ] 示例素材允许再分发；
- [ ] Schema和模板版本一致；
- [ ] 自动测试通过；
- [ ] README命令可运行；
- [ ] CHANGELOG已更新。
